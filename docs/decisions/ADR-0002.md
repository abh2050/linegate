# ADR-0002: Gate 1 training dependencies

Status: accepted

## Decision

- `lightgbm` is the classifier (declared in the stack). On macOS its wheel
  links `libomp`, installed with `brew install libomp`.
- `numpy` is imported directly for the feature matrix and the MCC sweep. It
  was already a transitive dependency of LightGBM; it is now declared.
- Polars is not used yet. DuckDB's `fetchnumpy` fills the matrix without a
  frame library or pyarrow.

## Known optimism

Gate 1 uses the validation split for early stopping and for choosing the MCC
threshold, then reports MCC on the same split. The reported number is
therefore slightly optimistic. The sealed holdout at Gate 7 is the honest
figure.

## First run (2026-09-14)

Validation MCC 0.1559 at threshold 0.733, AUC 0.592, 254 features, 21 s
end to end on an M3 Pro. Early stopping selected iteration 1. Diagnostics
(no config change): dropping route_code gives the same result;
scale_pos_weight=1 gives AUC 0.613 / MCC 0.162 at iteration 20; running
400 rounds with auto weighting never beats iteration 1 by more than 0.001
AUC. The trainer is not broken; the baseline aggregates carry weak signal,
with one split doing most of the work. Raising that signal is Gate 4's job.
