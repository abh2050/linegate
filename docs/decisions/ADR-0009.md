# ADR-0009: Holdout result

Status: recorded. The holdout has been run once (`data/holdout_runs.json` = 1)
and cannot be rerun.

## Result

| | Validation (rehearsal) | Holdout |
|---|---|---|
| Parts / failures | 236,643 / 728 (0.31%) | 236,616 / 964 (0.41%) |
| MCC at threshold 0.185 | 0.2267 | 0.1100 |
| AUC | 0.626 | 0.563 |
| Average precision | 0.076 | 0.030 |
| Abstain share | 37.2% | 25.7% |
| Escaped failures | 327 of 728 | 629 of 964 |
| $/shift, policy vs ship-all | 12,361 vs 15,177 | 18,010 vs 20,099 |

The rehearsal reproduced the recorded validation MCC exactly, so the
evaluation path is not at fault.

## Likely causes, not verified on the holdout

- Time drift. The holdout is the latest 20 percent of production time; the
  models saw only the earliest 60 percent. The failure rate moves from 0.73
  percent (train) to 0.31 (validation) to 0.41 (holdout), so the process
  itself changed across the three periods.
- The models were never refit on train plus validation before the holdout
  run, so they are one full period staler than necessary.
- The threshold (0.185) and the abstain band were chosen on validation, where
  the score distribution differs from the holdout's.

## Consequences

- The honest holdout MCC (0.110) is below the 0.15 to 0.30 range CLAUDE.md
  expects and below the Gate 1 floor of 0.12. It is reported as is.
- The policy still beats shipping everything on the holdout by about $2,090
  per shift (10 percent), down from 19 percent on validation.
- Any further holdout analysis would be a second look at sealed data; none
  was done. Future model changes need a new time-ordered holdout drawn from
  data after this one, with retraining on all prior periods and a scheduled
  threshold recalibration.
