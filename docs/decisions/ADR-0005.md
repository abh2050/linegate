# ADR-0005: Warden noise floor and search stop rule, after the first Gate 4 run

Status: accepted

## What happened

The first `make gate-4` run (traces `hypothesis-*` and `warden-search-*`
from 2026-09-14) failed. The agent made three proposals:

- `l3_s30_spread` quarantined: strict time refit, time lift 0.000 vs random
  lift 0.007. That random lift is below the standard error of AUC at about
  1,000 positives (~0.01), so the retention ratio was noise.
- `l3_s29_spread` quarantined: time lift 0.000 vs random lift 0.041. A real
  failure to transfer across time.
- `l3_s35_normspread` approved, evaluated at MCC 0.2078 (delta -0.019).

Quarantines counted toward the three-failure stop rule, so the search ended
after one evaluation.

## Decision

- `warden.min_lift` rises from 0.005 to 0.02, about two standard errors.
  Below it, shuffle collapse and time retention are treated as
  uninformative, as before. The row scope check is unaffected. Gate 3 was
  re-run after the change and still quarantines both leaks and approves all
  three controls.
- The stop rule counts only evaluate calls that fail to clear the bar, which
  matches the CLAUDE.md wording ("proposals fail to clear the minimum
  delta"). Quarantines still consume budget.

## Integrity note

The noise floor was changed after seeing a search-agent proposal, which
CLAUDE.md warns against. The change does not weaken any leak test: the
known leaks are caught by row scope and Id shuffle with lifts far above the
floor. Quarantines issued under the old floor remain final in
`data/feature_registry.json`.
